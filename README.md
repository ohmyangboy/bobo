# bobo

本地技能与智能体管理界面：技能基于 `npx skills` 呈现与管理，智能体直接管理 `~/.config/opencode/agents`（OpenCode）与 `~/.codex/agents`（Codex CLI）下的定义文件。原生 HTML / CSS / JavaScript + Node.js 内置 HTTP 服务，无运行时依赖、数据库或构建步骤。

## 启动

需要 Node.js 22+ 和 npm。双击 `start.command`，或在此目录运行 `npm start`，然后打开 http://127.0.0.1:4318 。终端保持运行，Ctrl+C 关闭。首次 npx 运行可能需要网络下载 Skills CLI。

## 功能

- 用 `npx skills list -g --json` 读取全局技能，按 Matt Pocock、Emil Kowalski 等作者或来源分组，显示数量；支持按名称、描述与来源搜索。覆盖 CLI 可发现的技能，不扫描 Codex 插件内部缓存。
- 详情页可一键在默认浏览器打开当前技能的来源地址（如 GitHub 仓库）；无来源地址的本地技能不显示该按钮。
- 浏览 SKILL.md 和子目录文件：文件按目录折叠（默认收起，当前文件所在的目录自动展开），点文件夹行展开或收起，点文件打开；编辑文本、创建和删除文件，⌘S 保存；修改冲突时拒绝覆盖。
- 仓库安装、社区搜索、本地创建分别调用 `add`、`find`、`init`。
- 「我的 Skill」可添加任意位置的技能目录并自动链接到 `~/.agents/skills`，按目录分组管理，支持新建技能、重新链接和一键同步到 GitHub。
- 顶栏的「智能体」视图管理两家的自定义智能体定义：OpenCode（如 `@design-ui-designer` 这类 subagent，`~/.config/opencode/agents`）与 Codex CLI（`~/.codex/agents`）；阅读/编辑、新建、重命名、停用/启用（仅 OpenCode）与删除，修改前都会备份；详见下文。
- 点击侧边栏分组行的任意位置（左侧三角、名称或空白处）都会选中该分组并显示它的「文件夹」视图：列出该来源分组下的全部技能，可在这里刷新、在 Finder 打开、全部更新或全部删除；同时切换该分组的展开/收起（点已展开的分组就收起来）。启动后停在第一个分组的文件夹视图，不自动打开某个技能。分组操作复用同一套 CLI 流程：`remove <...names> -g -y`、`update <...names> -g -y`；全部删除不备份，全部更新修改前备份。在文件夹里点某个技能进入详情，详情顶部可返回文件夹。`Finder` 打开该分组技能的公共父目录；本地技能分散在多个 Agent 目录、没有统一父目录时会提示无法打开。
- 命令行面板贴在窗口右下角，默认收起：点右下角的小凸起按钮展开或收起，点面板以外的任意位置也会收起；由「更新」「添加」等按钮拉起的命令会自动展开，并在结束 2 秒后自动收起，而用户手动展开的面板不会被自动收起（输出保留，可再次展开查看）。面板直接运行 `npx skills` 子命令，支持带引号的参数；显示输出和退出码。全局管理自动补上 `-g`，修改命令补上 `-y`。不支持交互式终端和 shell 管道。
- 仓库未指定技能时，CLI 可能安装整个仓库；可使用 `owner/repo@skill` 或指定技能字段。
- 文件树跳过隐藏文件、符号链接和 node_modules；文本编辑限制为 1 MB，其他文件可通过 Finder 打开。
- 通用设置集中在「设置」页：从左侧边栏左下角的「设置」按钮打开（顶栏出现带 × 的「设置」tab，关闭后回到原来的视图，页面左上角的「返回」同样关闭）。设置页左边是分类导航（外观 / AI / 关于），右边是按功能分区的卡片、控件在行尾右对齐；刘海与菜单栏相关的选项不在这里，都归「通知岛」视图。外观默认跟随系统深浅色：系统切换外观时界面即时更新，无需重启；在「设置 → 外观」里可改为固定「浅色」或「深色」，选择保存在浏览器本地（`localStorage` 的 `bobo-theme`，会兼容读取旧的 `skills-theme`），只影响本机界面，不改动系统设置。

## 备份

编辑文件前备份该技能；安装或更新前备份 CLI 当前列出的全部技能和全局锁文件；智能体的保存、重命名、删除与启停前备份定义文件。位置：`~/.bobo/backups/<时间>-<操作>/`。**只保留最近 3 份，超出自动淘汰最旧的**（技能与智能体共用配额），服务启动时也会清理一次。

删除技能时不进行备份，直接彻底删除整个技能目录及相关文件。

每份 `manifest.json` 记录原目录和备份目录的对应关系。可从备份复制所需文件回原目录；锁文件备份不应在已有其他安装变更时直接覆盖。

界面不修改 CLI 的来源、分组元数据。重装或更新后仍按 Source 分组。

## 我的 Skill

「我的 Skill」用来管理 `npx skills` 全局目录之外的本地技能目录。配置好的目录会一直作为侧栏顶部的「我的 · <目录名>」分组出现；选中它进入文件夹视图，右上角的「管理目录…」打开目录列表（添加、查看状态、移除，入口放在这里而不是顶栏）：

- 点「选择…」用系统文件夹选择器挑目录（弹窗里能直接新建文件夹），也可以手输路径（支持 `~/...`，不存在会自动创建；非 macOS 只能手输）。目录里的每个技能——直接子目录，或目录自身含 `SKILL.md`——会自动在 `~/.agents/skills` 建立指向源目录的符号链接，所有 Agent 立即可用，`npx skills list -g` 也能发现它们。配置保存在 `~/.bobo/sources.json`。
- 列表里这些技能归到「我的 · <目录名>」分组，排在其他来源之前，与 CLI 安装的技能区分。
- 名称冲突（`~/.agents/skills` 已有同名真实技能或指向别处的链接）不会覆盖，只在管理面板标记「名称冲突」，处理后点「重新链接」。
- 「新建技能」在目录下生成 `<名称>/SKILL.md` 并自动链接；「重新链接」会补齐缺失链接并清理指向本目录的失效链接。
- 删除技能会同时删除源目录里的文件夹与对应链接；「移除」只删除配置和链接，保留文件。
- 在文件夹视图里可以按需启停单个技能：关掉卡片右上角的开关只删除 `~/.agents/skills` 里的链接，源文件保留，Agent 不再看到它；重新打开开关即恢复链接。停用记录保存在 `sources.json` 的 `disabled` 数组，「重新链接」「一键同步」不会重新启用已停用的技能，删除技能或新建同名技能会清理停用记录。

**一键同步到 GitHub**：在目录卡片或文件夹视图里点「同步到 GitHub」。没有远程时用 `gh repo create` 新建仓库（可选 Private/Public）并推送；已有远程时可填入地址（`git@` 或 `https://`）推送。同步流程为 `git add -A` → 提交 → 推送，需要本机有 `git`，新建仓库需要已登录的 `gh`；提交自动关闭 GPG 签名，缺少提交身份时会用 `gh` 的登录名配置仓库级 `user.name`/`user.email`。推送后其他人可用 `npx skills add owner/repo` 安装。

## 智能体

顶栏的「智能体」视图管理两家的自定义智能体，用左侧顶部的开关切换来源：**OpenCode**（`~/.config/opencode/agents/**/*.md`，例如 `@design-ui-designer` 这类 subagent）与 **Codex CLI**（`~/.codex/agents/**/*.toml`）。这类配置没有 CLI 可以管理：`npx skills` 只管理技能，`opencode` V2 与 Codex 也都没有 agent 子命令，也没有社区标准；所以直接管理定义文件。

- 每个 `.md` 文件就是一个智能体：**文件名（含子目录）就是 ID**，frontmatter 是配置（`description`、`mode`、`model`、`permissions`、`color`、`hidden`、`disabled` 等），正文是系统提示词。
- 支持阅读、编辑、新建、重命名、停用/启用与删除；保存、重命名、删除、启停前都会备份到 `~/.bobo/backups/<时间>-agent-<操作>/`（与技能备份共用「最近 3 份」的配额）。编辑带版本校验，文件被其他程序修改时拒绝覆盖。
- 停用会在 frontmatter 写入 `disabled: true`（启用时移除），文件保留，OpenCode 不再加载它；重命名会改变 ID，已有会话对旧 ID 的引用会失效，界面会先提示。
- 列表会标出解析问题：缺少 frontmatter 或 `description`、`mode`/`color` 无效、文件名不符合 ID 规则。frontmatter 里的 `name` 字段在 V2 不生效（ID 由文件名决定），只在属性面板里展示。
- 保存后 OpenCode 会自动重新加载（实测增删文件约 2 秒内生效），无需重启；「Finder」可打开 `~/.config/opencode/agents`。
- 阅读视图支持「能力总结」和「翻译全文」：发送当前定义文件，翻译按段落上下对照显示；缓存位于 `~/.bobo/ai-cache/`，与技能缓存分开存放，同名互不影响。
- 只管理文件形式的定义，不修改 `opencode.json(c)` 里的 `agents` 字段（JSONC 注释难以安全改写）；`build`、`plan`、`general`、`explore` 等内置智能体没有文件，不在此列。

**Codex CLI（TOML）**：在「智能体」视图切到 Codex 后管理 `~/.codex/agents/**/*.toml`。每个文件定义一个 subagent，必填 `name`、`description`、`developer_instructions`，可选 `model`、`model_reasoning_effort`、`sandbox_mode`、`nickname_candidates`、`mcp_servers`、`skills.config` 等（省略时继承主会话）。支持阅读、编辑、新建、重命名与删除，写操作前同样备份（`~/.bobo/backups/<时间>-codex-agent-<操作>/`，与技能、OpenCode 智能体共用「最近 3 份」配额）；编辑带版本校验。**Codex 以 `name` 字段识别智能体**（文件名只是约定，界面会提示两者不一致），因此没有「停用」，重命名只移动文件、不改 `name`。列表会标出必填缺失、`model_reasoning_effort` / `sandbox_mode` 取值无效等问题。Codex 在新会话读取定义，改完重新开始一轮即可生效；「Finder」可打开 `~/.codex/agents`。能力总结与翻译同样支持，缓存与 OpenCode 智能体分开存放。

## 通知岛

顶栏第三个 tab「通知岛」把 OpenCode 与 Codex CLI 的工作状态变成看得见、听得到的提醒：

- 数据来自本机 OpenCode 服务的事件流（`GET /api/event`）：地址与密码读 `~/.local/state/opencode/service.json`（`XDG_STATE_HOME` 优先），服务没启动时静默等待，换端口会自动重连。bobo 不写 OpenCode 的任何配置。
- Codex CLI 没有事件流服务，bobo 改为轮询本机会话记录 `~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl`（只读最近两天、只看文件头尾）：`task_started` → 运行中，`task_complete` → 已结束，`turn_aborted` → 已终止，标题读 `~/.codex/session_index.jsonl`。只读，同样不写 Codex 的任何配置；侧栏的「Agent 连接」里有 OpenCode 与 Codex 两栏，各自显示来源与实时会话列表。
- 会话状态按事件推导：`session.inbox.enqueued` / `session.execution.started` → 运行中，`form.created`（智能体提问）与 `permission.asked` → 等你回答，`session.execution.succeeded` → 已结束，`failed` / `interrupted` → 已终止；`session.renamed` 与首次连接的会话列表提供标题与目录。
- 提醒默认开启：系统通知（`osascript`）与提示音（`afplay`，提问 Ping、结束 Glass、终止 Basso）。会话列表按**最近一次状态变更**排序：谁刚变了状态（开始运行、等你回答、结束、终止）谁就排到最上面；工具调用、文本输出这类活动不会让列表来回跳，等待回答的行仍然高亮。
- 设置保存在 `~/.bobo/opencode.json`：**系统通知**、**提示音**、**显示刘海面板**、**需要回答或结束时自动展开**、**没有活跃会话时隐藏**、**列表显示条数**（1–6）、**显示状态栏图标**（默认关）、**刘海面板可移动**、**显示器**。页面左侧分两组：**通知岛设置**（提醒 / 刘海面板 / 菜单栏与位置）与 **Agent 连接**（OpenCode 与 Codex，条目右侧的状态点跟着各自最新会话变色；连接状态与实时会话列表都在这一栏里）。
- **点击会话跳到 Otty**：Otty 的 opencode 集成会把标签页标题设成 `OC | <会话标题>`，Codex 的标签前缀以 Otty 实际显示为准（bobo 会依次尝试 `CX | `、`Codex | `、`CDX | `）；所以先按标题精确匹配，其次按目录（该目录下只有一个标签页时），命中就用 `otty-cli tab focus` 切过去并激活 Otty；找不到对应的标签页就只打开 Otty。刘海面板和通知岛列表都可以点；**也可以自己切到那个标签页**——Otty 在前台、且正停在这个会话的标签页上时同样算「看过了」，结束 / 终止后留在刘海上的头像随之消失。

**刘海面板**：macOS 应用在刘海位置常驻一条深色胶囊（与刘海同高、顶部贴住屏幕顶边、比菜单栏高两级），显示最需要关注的会话——蓝点脉冲=运行中、橙点=等你回答、绿点=已结束、红点=已终止；折叠时每个会话头像下方的指示灯也用状态色，运行中 / 等你回答会缓慢呼吸，结束与终止后的头像不会马上消失，要等你切到它的终端（自己切到那个标签页，或点会话行跳过去）才收起。齿轮左边还有一枚额度指示（见下文「用量」）：环形进度 + 来源图标 + 当前这一家的剩余百分比，点击在两家之间切换，悬停看两家明细。鼠标悬停向下展开会话卡片（条数由设置决定），点击回到 bobo 窗口；有会话等你回答时会自动展开 3 秒，运行结束或终止时自动展开 2 秒，没有操作就收回，鼠标移上去就不再自动收起。关闭主窗口后依然显示；关掉「显示刘海面板」后窗口整块收起，不挡点击。面板显示在哪块屏由通知岛里「菜单栏与位置」的**面板显示位置**决定：**自动**（默认）跟随你当前使用的应用所在屏幕，拿不到就回到刘海屏；也可以固定成**内置刘海屏**或**主显示器**（带菜单栏的那块，不是「当前正在操作的屏幕」）。插拔显示器、改分辨率或切换排列后会自动重贴到所选屏幕顶边。

**状态栏**（默认关闭，可在通知岛的「菜单栏与位置」里打开）：图标右下角跟着状态变色（运行蓝、等待橙、结束绿、终止红），悬停提示写明当前会话，右键菜单第一行显示状态，并可直接打开「通知岛」。

## 用量

顶栏第四个 tab「用量」把两家的额度集中显示；刘海面板折叠态的胶囊里也会显示当前这一家的剩余额度（齿轮左边：环形进度 + 来源图标 + 剩余百分比，点击切换来源、悬停看两家的完整明细）。

- **Codex**：读 `~/.codex/auth.json`（`CODEX_HOME` 优先）里的 OpenAI 登录信息，请求 ChatGPT 的额度接口，窗口按长度归类成「5 小时滚动 / 本周」。只读取凭据：不刷新 token、不回写文件；登录过期会提示在终端运行一次 `codex`（它会自己刷新），只配了 API Key 时会说明额度需要 ChatGPT 订阅。
- **OpenCode Go**：额度百分比与重置时间来自官方用量接口 `opencode.ai/zen/go/v1/usage`（口径与 CodexBar 一致：接口返回的 `percent` 是「已用百分比」，`rate-limited` 表示该窗口已经限额）。Key 的读取顺序是：**「用量 → OpenCode Go → API Key」里手动填写的 Key** → 环境变量 `OPENCODE_API_KEY` → `~/.local/share/opencode/auth.json` 里 opencode-go 的本机登录；手动 Key 保存前会先调一次接口验证，页面不回显已保存的 Key（只显示尾号）。接口不可用时退回本机估算：只读 `~/.local/share/opencode/opencode.db` 里 `opencode-go` 的调用费用，按 5 小时 $12 / 本周 $30 / 账单月 $60 折算（步骤级费用优先、周窗口按 UTC 周、账单月按本机最早一条记录锚定），数据库没有 `-wal/-shm` 时用 immutable 模式直读、不会在 OpenCode 目录里新建文件。两种情况下页面下方都会列出最近 30 天的每日花费与按模型汇总（来自本机数据库）。
- 数据每 60 秒刷新一次（走接口时最快 3 分钟一次，避免频繁请求）；网络失败时保留上一次成功的数据并标出错误。停留在「用量」页面时每分钟拉取一次，也可以点右下角的悬浮「刷新额度」按钮。
- 刘海胶囊显示哪一家可以点击切换（在**开启的**来源之间循环）；每个来源在「用量」页面里都有一条启停开关，关掉的来源只在这里查看、不参与刘海胶囊的切换。选择与启停都保存在 `~/.bobo/usage.json`（权限 0600，手动填的 API Key 也放在这里）。数据是本机估算（OpenCode Go 的降级路径）或账号返回值（Codex 与官方接口），不会写入任何远端状态。

## 验证

`npm test` 使用临时 HOME 和模拟 CLI，检查文件 CRUD、编辑冲突、符号链接/路径限制、请求校验、命令参数与更新前备份。不会更新或删除真实技能。真实 CLI 的远程安装和更新取决于网络与上游仓库状态。

智能体测试同样使用临时 HOME：OpenCode 覆盖 frontmatter 解析、子目录 ID、新建/重命名/删除、版本冲突、停用写回、路径保护、符号链接不可写与操作前备份；Codex 覆盖 TOML 顶层字段解析、必填/枚举校验、新建/重命名/删除、版本冲突、路径保护与操作前备份。

`我的 Skill` 的测试同样使用临时 HOME：用本地裸仓库和模拟 `gh` 验证目录添加、符号链接、名称冲突、删除与 Git 提交流程，不访问 GitHub、不推送真实仓库。

通知岛的测试用模拟 OpenCode 服务（本地 HTTP + SSE）：验证会话按最近一次状态变更排序、活动事件不重排、结束与终止的会话顶到最前，以及「已查看终端」标记的置位与重置；Otty 的会话/标签页匹配与 active 判定是纯函数，单独测试。Codex 会话用临时 HOME 里合成的 rollout 文件测试：状态推导、结束/终止的挂起提醒、重新开始后重新标记未查看。

只监听本机 127.0.0.1，不适合直接部署到公网。`PORT` 可更换端口；`BOBO_HOME`、`BOBO_NPX` 用于隔离测试。

## macOS 应用

已安装到 `/Applications/bobo.app`。应用默认只保留屏幕顶部的刘海面板，不在菜单栏放图标；同时按窗口状态在 Dock 中动态出现：窗口打开时是普通应用，会进入 Dock 与 ⌘Tab 切换器，关闭窗口后自动从 Dock 与 ⌘Tab 中隐藏。刘海右侧有一个齿轮按钮，点它（或点刘海其它位置）打开主窗口；如果更习惯菜单栏入口，可以在「通知岛 → 菜单栏与位置」打开「显示状态栏图标」，恢复菜单栏图标与它的右键菜单。

应用使用系统 AppKit + WebKit，界面按 macOS 原生观感绘制并跟随系统深/浅色（也可在「设置 → 外观」里固定）：窗口没有原生标题栏，顶栏与红黄绿灯连成一体：应用图标与应用名贴顶居中，和红黄绿灯同处一条水平线，下面一行左侧是「技能 / 智能体 / 通知岛」tab 标签（「设置」在打开时才出现，带 × 关闭），右侧是「技能」视图的操作按钮。首次打开时自动启动内置的本地服务。打开状态栏图标后，左键点击它切换窗口显示/隐藏，右键（或 Control+左键）弹出菜单，可打开 bobo、跳到通知岛、重置刘海位置或退出；刘海面板始终可用。关闭窗口（红灯或 ⌘W）只会隐藏界面，应用继续驻留；⌘Q 或菜单里的「退出」才会结束自己启动的服务。如果服务已由终端启动，则复用并保留该服务。

应用包包含网页与服务的独立副本，仍使用本机 Node.js / npm。源码变更后运行 `./macos/update` 即可：自动构建并覆盖安装 `/Applications/bobo.app`，退出正在运行的旧应用后打开新版本；可传路径参数指定其他安装位置。构建先写到临时目录，失败不会破坏已安装版本。改名后首次运行时，旧安装 `/Applications/Skills Manager.app` 会被自动退出并移除，数据目录 `~/.skills-manager` 的内容会逐项迁移到 `~/.bobo`（`~/.bobo` 里已存在的文件不会被覆盖）。

## 启动速度

成功扫描后将列表保存到 `~/.bobo/catalog.json`（单个覆盖写入的快照，不累积备份）。下次启动先显示快照并在后台同步最新列表；不存在快照时需要等待首次 CLI 扫描。已删除目录会先过滤，手动刷新和修改类 CLI 操作使用最新扫描结果。

## AI 翻译与能力总结

「设置 → AI」可配置 OpenAI 兼容 API 地址（例如 `https://api.deepseek.com`）、模型和 Key 来源。接口须支持 `/chat/completions`；可使用兼容网关或本机服务。技能与智能体共用同一套能力：技能面向 SKILL.md 与子文件，智能体面向单个定义文件，分段对齐、分批翻译与缓存规则一致。

- **读取系统**：优先使用服务进程的 `OPENAI_API_KEY`，macOS 下缺失时读取 `launchctl getenv OPENAI_API_KEY`，再尝试 `~/.zshrc`；也可选择「读取 ~/.zshrc 的 OPENAI_API_KEY」直接使用文件配置。支持 `export OPENAI_API_KEY="..."`、单引号及无引号的单行字面量赋值和行尾注释，重复赋值取最后一项。不支持变量展开、命令替换、跨行或 source 引用，不执行 shell 文件。未手动保存地址、模型时，分别读取 `OPENAI_BASE_URL` 和 `OPENAI_MODEL`，默认使用 DeepSeek 地址和 `deepseek-v4-flash`。在终端通过 `npm start` 启动会继承终端的环境变量；Finder 启动的应用通常不会继承 `.zshrc`，可直接选择读取 ~/.zshrc，或使用手动配置及已有的 launchctl 环境。不会扫描其他应用的凭据文件。
- **手动配置**：Key 保存在 `~/.bobo/ai.json`，文件权限为 `0600`，属于本地明文配置；不进入技能备份。页面只接收是否配置及来源，不回显 Key。留空保持原 Key，可单独清除已保存 Key。
- **能力总结**：在正文顶部点击生成，说明技能用途、核心能力、适用场景、输入产出、示例和限制。生成时实时流式显示，可展开、收起或复制，不再弹出结果窗口。
- **翻译全文**：对当前打开的文件（SKILL.md 或任意子文件）按段落显示「原文在上、中文在下」，按钮位于阅读/编辑切换区右侧；同一分段规则与稳定段落 ID 保证对齐。代码块只保留原文；声明块默认展开（可手动折叠，折叠状态在重新渲染时保留），字段以键值表格显示，展开后可查看字段与译文的对照。首批优先翻译 2 段，其余每批最多 6 段、最多两批并行；完成一批立即推送到正文并缓存，失败后点击「继续翻译」只请求尚未完成的段落。不同文件各自缓存，互不覆盖。

默认使用排版后的阅读视图，可切换「编辑」操作原始文件。点击能力总结时只发送当前技能**已保存的 SKILL.md**，点击翻译时发送当前打开文件的已保存内容到所配置服务；不执行文档中的指令。修改须先保存才能切换阅读或生成。

摘要和译文持久化于 `~/.bobo/ai-cache/`，刷新页面、重启应用均可复用。缓存绑定技能文件版本、目录身份、目标文件路径、模型、API 地址和提示词版本。编辑技能文件、支持文件变化、更新或删除技能时失效；即使更新后正文没变，也需要重新生成。同路径重新安装不会复用旧缓存，更新过程中迟到的 AI 响应不会恢复已失效的缓存。AI 配置变更后使用新缓存；Key 不写入缓存。

支持不超过 180 KB 的单个文件；每次模型请求最长 120 秒。DeepSeek 模型的摘要与翻译均显式发送 `thinking: {"type":"disabled"}`，关闭思考。摘要使用 SSE 接收增量，再通过本地流式响应直接推送页面；兼容服务若返回普通 JSON，也能显示结果，不额外重发请求。切换技能不会把生成结果插入其他技能，返回或刷新后可继续查看进度。全文完成后可复制译文，摘要可独立复制，均不改写原始文件。AI 输出需对照原文核实。

顶部与技能工具栏按使用频率分层：主要动作直接可见，低频与破坏性操作收进「⋯」菜单（删除类操作在菜单底部独立成行）。菜单支持点击面板以外或按 Esc 收起，按钮均带悬停提示并支持键盘焦点与减少动态效果偏好。

`npm test` 还包含隔离的模拟 AI 接口测试，覆盖系统 Key、配置持久化和权限、翻译/总结请求、鉴权/额度错误、重定向拒绝及失败恢复；正文缓存测试还覆盖持久化、逐段对齐、续译、更新/重装失效和迟到响应。测试不会使用真实 API Key 或消费模型额度。

流式回归测试覆盖首字在请求结束前到达、跨网络块的中文 UTF-8、关闭思考参数，以及双批次并发和缓存完整性。
