# 功能详解

本文档是 bobo 的完整功能与实现说明；[README](../README.md) 只保留简介、支持列表与快速开始。

## 启动

需要 Node.js 22.13+（不再需要 npm）。双击 `start.command`，或在此目录运行 `npm start`，然后打开 http://127.0.0.1:4318 。终端保持运行，Ctrl+C 关闭。从仓库安装/更新技能需要本机有 `git`（公开仓库用 https，私有仓库用你已配置的凭据或 SSH）。

## 功能

- 直接扫描 `~/.agents/skills` 与各个已安装 Agent 的全局技能目录读取全局技能，按 Matt Pocock、Emil Kowalski 等作者或来源分组，显示数量；支持按名称、描述与来源搜索。只收录 frontmatter 里 `name` 与 `description` 都非空的技能，与 Agent Skills 生态的约定一致。
- 详情页可一键在默认浏览器打开当前技能的来源地址（如 GitHub 仓库）；无来源地址的本地技能不显示该按钮。
- 浏览 SKILL.md 和子目录文件：文件按目录折叠（默认收起，当前文件所在的目录自动展开），点文件夹行展开或收起，点文件打开；编辑文本、创建和删除文件，⌘S 保存；修改冲突时拒绝覆盖。
- 仓库安装、本地创建分别对应「添加技能」里的两种方式。
- 「我的 Skill」可添加任意位置的技能目录并自动链接到 `~/.agents/skills`，按目录分组管理，支持新建技能、重新链接和一键同步到 GitHub。
- 顶栏的「智能体」视图管理两家的自定义智能体定义：OpenCode（如 `@design-ui-designer` 这类 subagent，`~/.config/opencode/agents`）与 Codex CLI（`~/.codex/agents`）；阅读/编辑、新建、重命名、停用/启用（仅 OpenCode）与删除，修改前都会备份。左栏还能切到「全局配置」，阅读并调节「通知岛」已接入的 harness（OpenCode、Codex、Claude Code、omp、dsh、agy）的全局个性化与配置文件，尚未创建的文件可以直接写并保存；未接入通知岛的 Agent 暂不开放（白名单里已注释保留）；详见下文。
- 点击侧边栏分组行的任意位置（左侧三角、名称或空白处）都会选中该分组并显示它的「文件夹」视图：列出该来源分组下的全部技能，可在这里刷新、在 Finder 打开、全部更新或全部删除；同时切换该分组的展开/收起（点已展开的分组就收起来）。启动后停在第一个分组的文件夹视图，不自动打开某个技能。分组操作按来源筛选后逐个子命令执行：删除直接删除技能目录与各 Agent 链接（不备份），更新前会备份。在文件夹里点某个技能进入详情，详情顶部可返回文件夹。`Finder` 打开该分组技能的公共父目录；本地技能分散在多个 Agent 目录、没有统一父目录时会提示无法打开。
- 右下角的「任务输出」是只读抽屉，默认收起：点小凸起按钮展开或收起，点抽屉以外的任意位置也会收起；由「更新」「添加」等操作自动拉起的会在结束 2 秒后自动收起，而用户手动展开的抽屉不会被自动收起（输出保留，可再次展开查看）。里面显示安装/更新/删除的进度与结果、以及失败原因（例如 git 报错），不再是可输入命令的终端。
- 从仓库安装时支持 `owner/repo`、GitHub 树链接、任意 Git 地址与本地目录；不指定技能名时安装仓库里的全部技能，也可以用「只安装指定技能」按名称挑选；同一个技能的旧版本会被替换（替换前先备份），同名「我的技能」不会被覆盖。
- 文件树跳过隐藏文件、符号链接和 node_modules；文本编辑限制为 1 MB，其他文件可通过 Finder 打开。
- 通用设置集中在顶栏最后一个常驻 tab「设置」：左边是分类导航（外观 / AI / 关于），右边是按功能分区的卡片、控件在行尾右对齐；「关于」里能看到当前版本、作者与许可、检查更新（新版本下载完成后一键重启安装）以及 GitHub 仓库 / Releases / Issue 入口。刘海与菜单栏相关的选项不在这里，都归「通知岛」视图。外观默认跟随系统深浅色：系统切换外观时界面即时更新，无需重启；在「设置 → 外观」里可改为固定「浅色」或「深色」，选择保存在浏览器本地（`localStorage` 的 `bobo-theme`，会兼容读取旧的 `skills-theme`），只影响本机界面，不改动系统设置。
- 顶栏的「设备」视图监控本机 CPU、内存与磁盘（只读、不联网、不写任何文件），刘海胶囊的额度右边也有一枚设备指示；详见下文。

## 备份

编辑文件前备份该技能；安装或更新前备份当前全部技能和全局锁文件；智能体的保存、重命名、删除与启停前备份定义文件。位置：`~/.bobo/backups/<时间>-<操作>/`。**只保留最近 3 份，超出自动淘汰最旧的**（技能与智能体共用配额），服务启动时也会清理一次。

删除技能时不进行备份，直接彻底删除整个技能目录、各 Agent 目录里的链接与锁文件记录。

每份 `manifest.json` 记录原目录和备份目录的对应关系。可从备份复制所需文件回原目录；锁文件备份不应在已有其他安装变更时直接覆盖。

来源与分组元数据保存在全局锁文件 `~/.agents/.skill-lock.json`（`XDG_STATE_HOME` 优先）里，格式与 skills 生态一致，bobo 与 `npx skills` 可以互相读取。重装或更新后仍按 Source 分组。

## 我的 Skill

「我的 Skill」用来管理全局技能目录（`~/.agents/skills`）之外的本地技能目录。配置好的目录会一直作为侧栏顶部的「我的 · <目录名>」分组出现；选中它进入文件夹视图，右上角的「管理目录…」打开目录列表（添加、查看状态、移除，入口放在这里而不是顶栏）：

- 点「选择…」用系统文件夹选择器挑目录（弹窗里能直接新建文件夹），也可以手输路径（支持 `~/...`，不存在会自动创建；非 macOS 只能手输）。目录里的每个技能——直接子目录，或目录自身含 `SKILL.md`——会自动在 `~/.agents/skills` 建立指向源目录的符号链接，所有 Agent 立即可用，`npx skills list -g` 也能发现它们。配置保存在 `~/.bobo/sources.json`。
- 列表里这些技能归到「我的 · <目录名>」分组，排在其他来源之前，与从仓库安装的技能区分。
- 名称冲突（`~/.agents/skills` 已有同名真实技能或指向别处的链接）不会覆盖，只在管理面板标记「名称冲突」，处理后点「重新链接」。
- 「新建技能」在目录下生成 `<名称>/SKILL.md` 并自动链接；「重新链接」会补齐缺失链接并清理指向本目录的失效链接。
- 删除技能会同时删除源目录里的文件夹与对应链接；「移除」只删除配置和链接，保留文件。
- 在文件夹视图里可以按需启停单个技能：关掉卡片右上角的开关只删除 `~/.agents/skills` 里的链接，源文件保留，Agent 不再看到它；重新打开开关即恢复链接。停用记录保存在 `sources.json` 的 `disabled` 数组，「重新链接」「一键同步」不会重新启用已停用的技能，删除技能或新建同名技能会清理停用记录。

**一键同步到 GitHub**：在目录卡片或文件夹视图里点「同步到 GitHub」。没有远程时用 `gh repo create` 新建仓库（可选 Private/Public）并推送；已有远程时可填入地址（`git@` 或 `https://`）推送。同步流程为 `git add -A` → 提交 → 推送，需要本机有 `git`，新建仓库需要已登录的 `gh`；提交自动关闭 GPG 签名，缺少提交身份时会用 `gh` 的登录名配置仓库级 `user.name`/`user.email`。推送后其他人可用 `npx skills add owner/repo` 安装。

## 智能体

顶栏的「智能体」视图管理自定义智能体定义：**OpenCode**（`~/.config/opencode/agents/**/*.md`，例如 `@design-ui-designer` 这类 subagent）与 **Codex CLI**（`~/.codex/agents/**/*.toml`），在左栏来源菜单里切换；同一视图还能阅读与调节这两家与 Claude Code、omp、dsh、Antigravity 的全局配置（见下文「全局配置」）。这类配置没有 CLI 可以管理：`npx skills` 只管理技能，`opencode` V2 与 Codex 也都没有 agent 子命令，也没有社区标准；所以直接管理定义文件。

- 每个 `.md` 文件就是一个智能体：**文件名（含子目录）就是 ID**，frontmatter 是配置（`description`、`mode`、`model`、`permissions`、`color`、`hidden`、`disabled` 等），正文是系统提示词。
- 支持阅读、编辑、新建、重命名、停用/启用与删除；保存、重命名、删除、启停前都会备份到 `~/.bobo/backups/<时间>-agent-<操作>/`（与技能备份共用「最近 3 份」的配额）。编辑带版本校验，文件被其他程序修改时拒绝覆盖。
- 停用会在 frontmatter 写入 `disabled: true`（启用时移除），文件保留，OpenCode 不再加载它；重命名会改变 ID，已有会话对旧 ID 的引用会失效，界面会先提示。
- 列表会标出解析问题：缺少 frontmatter 或 `description`、`mode`/`color` 无效、文件名不符合 ID 规则。frontmatter 里的 `name` 字段在 V2 不生效（ID 由文件名决定），只在属性面板里展示。
- 保存后 OpenCode 会自动重新加载（实测增删文件约 2 秒内生效），无需重启；「Finder」可打开 `~/.config/opencode/agents`。
- 阅读视图支持「能力总结」和「翻译全文」：发送当前定义文件，翻译按段落上下对照显示；缓存位于 `~/.bobo/ai-cache/`，与技能缓存分开存放，同名互不影响。
- 只管理文件形式的定义，不修改 `opencode.json(c)` 里的 `agents` 字段（JSONC 注释难以安全改写）；`build`、`plan`、`general`、`explore` 等内置智能体没有文件，不在此列。

**Codex CLI（TOML）**：在「智能体」视图切到 Codex 后管理 `~/.codex/agents/**/*.toml`。每个文件定义一个 subagent，必填 `name`、`description`、`developer_instructions`，可选 `model`、`model_reasoning_effort`、`sandbox_mode`、`nickname_candidates`、`mcp_servers`、`skills.config` 等（省略时继承主会话）。支持阅读、编辑、新建、重命名与删除，写操作前同样备份（`~/.bobo/backups/<时间>-codex-agent-<操作>/`，与技能、OpenCode 智能体共用「最近 3 份」配额）；编辑带版本校验。**Codex 以 `name` 字段识别智能体**（文件名只是约定，界面会提示两者不一致），因此没有「停用」，重命名只移动文件、不改 `name`。列表会标出必填缺失、`model_reasoning_effort` / `sandbox_mode` 取值无效等问题。Codex 在新会话读取定义，改完重新开始一轮即可生效；「Finder」可打开 `~/.codex/agents`。能力总结与翻译同样支持，缓存与 OpenCode 智能体分开存放。

**全局配置**：最左侧只放来源——只收录「通知岛」已接入的 harness（OpenCode、Codex、Claude Code、omp、dsh、agy），**已安装且存在配置**（配置目录与至少一份白名单文件都在）的排在前面、状态点为绿，其余置灰并且不亮图标之外的任何占位；未接入通知岛的 Agent 在白名单里注释保留，接入后再开放。内容区左边一列是搜索框 + 区块，**全局配置在上、智能体定义在下**（只有支持子智能体定义的来源才有这一块），一个搜索框同时过滤两块，右边是详情。全局配置区块会识别该来源的核心全局文件，直接阅读和编辑、快速调节：

- **OpenCode**（`~/.config/opencode/`）：`AGENTS.md`、`opencode.json` / `opencode.jsonc`、`cli.json`。
- **Codex**（`~/.codex/`，可用 `CODEX_HOME`）：`AGENTS.md`、`config.toml`。
- **Claude Code**（`~/.claude/`，可用 `CLAUDE_CONFIG_DIR`）：`CLAUDE.md`、`settings.json`、`keybindings.json`。
- **omp**（`~/.omp/agent/`，可用 `PI_CODING_AGENT_DIR`）：`config.yml` / `config.yaml`、`PERSONALITY.md`。
- **DeepSeek**（`~/.dsh/`，可用 `DSH_HOME`）：`settings.yaml`。
- **Antigravity**（`~/.gemini/`，可用 `ANTIGRAVITY_CONFIG_DIR`）：`GEMINI.md`、`settings.json`、`antigravity-cli/settings.json`、`config/config.json`、`config/hooks.json`、`config/mcp_config.json`。

来源菜单的图标一律是真实品牌图标（`index.html` 里的内联 SVG 精灵，与通知岛、用量视图同源），没有图标的来源不放图标、不做首字母色块占位。

只识别白名单里的固定文件，不会扫描目录，避免碰到 `auth.json`、`*.credentials.json` 之类的凭据；配置根目录支持 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 等环境变量。

尚未创建的文件也会列出来（标记「未创建」），点进去写上内容保存即可创建；已有文件保存前会备份到 `~/.bobo/backups/<时间>-config-edit/`（同样只保留最近 3 份），并带版本校验，文件被其他程序改动时拒绝覆盖。详情页复用智能体的阅读视图、编辑、能力总结与翻译（配置按 Markdown 分段，JSON / TOML 以原文编辑），但不提供重命名、停用与删除——这些是固定文件；「Finder」打开所在的配置目录。文件超过 1 MB 或是指向别处的符号链接时只读。

## 通知岛

顶栏第三个 tab「通知岛」把 OpenCode、Codex CLI、omp（Oh My Pi）、Claude Code、DeepSeek Harness（dsh）与 Google Antigravity（agy）的工作状态变成看得见、听得到的提醒：

- 数据来自本机 OpenCode 服务的事件流（`GET /api/event`）：地址与密码读 `~/.local/state/opencode/service.json`（`XDG_STATE_HOME` 优先），服务没启动时静默等待，换端口会自动重连。bobo 不写 OpenCode 的任何配置。
- Codex CLI 没有事件流服务，bobo 改为轮询本机会话记录 `~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl`（只读最近两天、只看文件头尾）：`task_started` → 运行中，`task_complete` → 已结束，`turn_aborted` → 已终止，标题读 `~/.codex/session_index.jsonl`。同一个会话可能有不止一份 rollout 文件（Codex 桌面版 rollover / fork 会另写一份 `<原会话id>_<新会话id>.jsonl`，meta 里仍是原 id），状态只按最新写入的那份算、开始时间取最早的一份，避免状态来回翻导致重复提醒。只读，同样不写 Codex 的任何配置。rollout 的 `session_meta` 里 `originator` / `source` 还记着这一轮是 **Codex 桌面版**（Codex app / ChatGPT.app：`Codex Desktop`、`codex_work_desktop`、`source=vscode` / `appserver`）还是 CLI（`codex-tui`、`codex_cli_rs`）跑的，点会话时据此决定跳 app 还是找终端。
- omp（Oh My Pi）也没有事件流服务，bobo 改为轮询它的会话日志 `~/.omp/agent/sessions/<目录>/<时间>_<会话ID>.jsonl`（只看最近 30 分钟有写入的文件头尾；`PI_CODING_AGENT_DIR` 优先）：回复收尾 → 已结束，`session_exit` 记录退出（正常结束 / 被信号终止），工具调用与运行中的记录 → 运行中，等你批准或 `ask` 提问 → 等你回答。只读，同样不写 omp 的任何配置。
- Claude Code 没有对外的事件流，但 bobo 能读两份本机信号：`~/.claude/sessions/<pid>.json` 是活跃会话注册表，`status` 直接给出 `busy`（运行中）/ `waiting`（等你回答，`waitingFor` 区分「权限确认」与「要你回答」）/ `idle`（已结束）；`~/.claude/projects/<目录>/<会话ID>.jsonl` 的 `ai-title` / `last-prompt` 提供标题，cwd 提供目录。进程退出时还在跑或等回答的按已终止处理。只读，同样不写 Claude Code 的任何配置。
- DeepSeek Harness（`dsh`）把每个会话的投影缓存写在 `~/.dsh/storages/session_projcache/sessions/<会话ID>.json`，bobo 按它推导状态：有正在跑的 turn / step 就是运行中，上一轮 `completed` 是已结束、`aborted` / `interrupted` 是已终止，模型请求进入 plan 模式（等你批准）时是等你回答；标题取会话的 AI 标题、目录取 `identity.cwd`。审批与 `ask_user` 的等待不写投影，因此那两种等待显示成运行中。只读，同样不写 dsh 的任何配置。**点 dsh 会话的跳转也按它的形态来**：dsh 的 web profile（本地页面 `127.0.0.1:3080`）在跑时，点击会**先切到浏览器里已经打开的那个 dsh 页面标签**（Chrome / Edge / Brave / Vivaldi / Chromium / Safari 都按标签 URL 找，带不带尾斜杠都认），没有才新开一个；连不上 3080（例如跑的是 tui profile）才去找终端标签页。
- Google Antigravity（`agy`）把每个会话的概要写在本机 SQLite 库里（`~/.gemini/antigravity-cli/conversation_summaries.db` 的 `conversation_summaries` 表，bobo 只读、不写 agy 的任何配置）：`status` 是运行中或 `not_fully_idle` 为 1 时算运行中（超过 15 分钟没有新写入就按已结束处理，免得一次中断留下永远转圈的头像），`killed` 为已终止，其余已结束；最新一步在等 `ask_question` 时算等你回答（读该会话 `brain/<会话 ID>/.system_generated/logs/transcript.jsonl` 的末尾；审批类的等待不写这里，所以那种等待显示成运行中）。标题取会话标题，目录取 `workspace_uris` 里的第一个 `file://` 路径。**子代理的会话不上面板**（`parent_conversation_id` 非空或 `nesting_depth > 0` 的过滤掉）。会话库是 SQLite，靠 Node 22.13+ 的内置 `node:sqlite` 读；运行时读不了（Node 太旧）时页面会直接说明原因，而不是显示成「没有会话」。点会话照常去找终端标签页（标题前缀 `AGY | ` 或 `Antigravity | `）。
- 侧栏的「Agent 连接」里有 OpenCode、Codex、omp、Claude Code、DeepSeek 与 Antigravity 六栏，各自显示来源与实时会话列表。
- 会话状态按事件推导：`session.inbox.enqueued` / `session.execution.started` → 运行中，`form.created`（智能体提问）与 `permission.asked`（权限确认）→ 等你回答，`form.replied` / `permission.replied` → 回到运行中，`session.execution.succeeded` → 已结束，`failed` / `interrupted` → 已终止；`session.renamed` 与首次连接的会话列表提供标题与目录。权限询问会先挂起 0.8 秒：自动模式（auto）立刻自动批准（`permission.replied`）时不会闪过「等你回答」、也不会提醒；真在等你回答才落定并提醒一次。
- 提醒默认开启：系统通知（`osascript`）与提示音（`afplay`，提问 Ping、结束 Glass、终止 Basso）。会话列表按**最近一次状态变更**排序：谁刚变了状态（开始运行、等你回答、结束、终止）谁就排到最上面；工具调用、文本输出这类活动不会让列表来回跳，等待回答的行仍然高亮。会话行第二行还会标出它跑在哪个终端（Otty / Ghostty / Terminal，Codex app 里跑的会话标成 Codex App）：归属只在通知岛视图打开或刘海面板展开时才去扫描终端标签页，收起 / 关掉后不再扫。会话行右侧还有一格**计时**（对齐 CodeIsland 的 SessionTag）：显示**会话开始至今**的时长（`<1m` / `5m` / `2h` / `1d`），每秒自己走一格；开始时间由各来源分别记录——OpenCode 用会话的 `time.created`、Codex 用 rollout 的 `session_meta.timestamp`、omp 用会话 header 的 `timestamp`、Claude Code 用活跃注册表的 `startedAt`、dsh 用投影缓存的 `identity.createdAt`，读不到就退回文件时间，认不出来的（老数据）不显示这一格。
- 设置保存在 `~/.bobo/opencode.json`：**系统通知**、**提示音**、**显示刘海面板**、**需要回答或结束时自动展开**、**没有活跃会话时隐藏**、**列表显示条数**（1–6）、**额度查看方式**（默认「展开并排」，可切回「点击切换」）、**并排显示数量**（3 / 5 / 7 / 自适应，默认自适应）、**默认展示的额度**（折叠胶囊显示哪一家，默认「自动」= 第一个可用来源；这一项与「用量」页点来源是同一个选择，存在 `~/.bobo/usage.json` 的 `provider`）、**显示状态栏图标**（默认关）、**刘海面板可移动**、**显示器**。页面左侧分两组：**通知岛设置**（提醒 / 刘海面板 / 内容 / 菜单栏与位置）与 **Agent 连接**（OpenCode、Codex、omp、Claude Code、DeepSeek 与 Antigravity，条目右侧的状态点跟着各自最新会话变色；连接状态与实时会话列表都在这一栏里）。
- **点击会话跳到对应终端**：支持 Otty、Ghostty、Terminal.app 三个终端，按这个顺序找——哪个终端已经打开着这个会话就跳哪个。Otty 走自带的 `otty-cli`，Ghostty 与 Terminal.app 走 AppleScript（首次会请求 macOS「自动化」权限）。匹配依据：Otty 的 opencode 集成与 OpenCode 的标题插件会把标签页标题设成 `OC | <会话标题>`（omp 是 `π <标题>`，运行中前缀后多一个 spinner；Claude Code 是 `✳ <标题>`；Codex 依次尝试 `CX | `、`Codex | `、`CDX | `；Antigravity 依次尝试 `AGY | `、`Antigravity | `），所以先按标题精确匹配；Ghostty 还能按工作目录精确匹配；再退到标题包含、目录名包含。命中后切到该标签页并激活；找不到对应标签页就激活正在运行的那个终端（都不在跑就打开第一个已安装的）。**Codex 桌面版（Codex app / ChatGPT.app）出身的会话先按标题找终端**：CLI `codex resume` 过的线程标题还在，认到了就跳那个标签页（同一个目录不算数，免得跳到同目录里另一条无关标签）；认不到、而 Codex app 正开着时才打开线程深链 `codex://threads/<会话 id>` 把用户带到 app 里那个线程；app 没在跑就不跳深链（免得把已经退出的 app 重新拉起来），照常找终端。CLI 会话在三个终端里一个标签页都没匹配到、而 Codex app 正开着时同样退到深链——比激活一个空终端有用。刘海面板和通知岛列表都可以点——**点过就算「看过了」，跳不过去也算**（终端页已经关掉、找不到对应标签页时，这一下就是把它收起来）；**也可以自己切到那个标签页**——该终端在前台、且正停在这个会话的标签页上时同样算「看过了」。结束 / 终止的会话一旦「看过」，就从通知岛列表与刘海头像里一起收起，不会一直残留。

**刘海面板**：macOS 应用在刘海位置常驻一条深色胶囊（与刘海同高、顶部贴住屏幕顶边、比菜单栏高两级），显示最需要关注的会话——蓝点脉冲=运行中、橙点=等你回答、绿点=已结束、红点=已终止；**子 agent 的子会话不会出现在这里**（OpenCode 按会话的 `parentID`、Codex 按 rollout 里的 `thread_source: subagent` 过滤掉），免得一次任务多出一串头像；折叠时每个会话头像下方的指示灯也用状态色，运行中 / 等你回答会缓慢呼吸，结束与终止后的头像不会马上消失，要等你处理过它（点一下会话行——终端页关掉、跳不过去也算；或自己切到那个标签页）才收起，会话行同时也从列表里消失，不会一直残留。**贴在真实刘海上时**（内置刘海屏）胶囊中间留给刘海：头像排在刘海左侧、额度与设备排在刘海右侧，都不会被摄像头模组盖住；折叠态最多显示 4 个会话头像，多出来的会话折成一枚「+N」徽标（被藏起来的里面有等你回答的会转成橙色提醒，完整列表展开看），面板固定锚定在刘海正中——「刘海面板可移动」的左右拖动只在外接屏上生效；外接屏没有刘海，胶囊按内容自适应变宽，最多显示 8 个头像。齿轮左边还有一枚额度指示（见下文「用量」）：一枚环形进度 + 来源图标（不显示百分比），鼠标停在上面半秒弹出一张明细卡（这一家的窗口、剩余百分比 / 金额、重置时间；并排显示时鼠标停在哪一枚圆环上就看哪一家），默认的**展开并排**方式在面板展开时把所有可用来源的额度圆环并排显示出来（数量按屏幕剩余空间自适应，可以在通知岛设置里改成最多 3 / 5 / 7 家，或切回「点击切换」），折叠态只留**默认展示的额度**（通知岛 → 内容里选，默认「自动」= 第一个可用来源；点「用量」页里的来源也能改，点圆环不会改它）——点「展开并排」里的某一枚圆环只在这一家的窗口之间循环（5 小时 / 本周 / 账单月…，每枚圆环各记各的）；「点击切换」方式则是点圆环在可用来源之间循环；额度指示的右边是设备指示（见下文「设备」）：外环上 260° 是磁盘占用、下 100° 是内存占用，各自按占用率变色（≥ 85% 红、≥ 75% 橙、健康色是磁盘白 / 内存青），中心圆点是 CPU 压力灯，鼠标停在上面半秒弹出 CPU / 内存 / 磁盘明细，点击打开「设备」视图。两张明细卡都是深色圆角小卡片、风格与面板一致，贴在鼠标下方，鼠标移开就收起。会话头像区右边有一条细竖线，把头像是状态图标分开（两边的间距和其它图标之间一样）。鼠标悬停向下展开会话卡片（条数由设置决定），点击回到 bobo 窗口；有会话等你回答时会自动展开 3 秒，运行结束或终止时自动展开 2 秒，没有操作就收回，鼠标移上去就不再自动收起；自动展开时，提醒对应的会话行会描一圈该提醒类型的颜色（等你回答橙 / 已结束绿 / 已终止红），这一圈和头像一样要等你到终端看过才消失，所以收起后展开仍能一眼看出是哪个会话。关闭主窗口后依然显示；关掉「显示刘海面板」后窗口整块收起，不挡点击（显示 / 收起都是淡入淡出，不会生硬地弹出来或闪掉）。**防遮挡时完全隐藏**：前台应用全屏、或鼠标移到菜单栏上时，面板会补间收拢到刘海正中并淡出到看不见（有真实刘海时最后那点内容正好消失在刘海区域里，外接屏就是淡出），窗口不 orderOut、但也不接收鼠标事件，所以不挡菜单栏 / 全屏内容上的点击；鼠标离开菜单栏、退出全屏后，再沿同一条「尺寸补间 + 淡入」长回来，全程不会硬切。面板显示在哪块屏由通知岛里「菜单栏与位置」的**面板显示位置**决定：**自动**（默认）跟随你当前使用的应用所在屏幕，拿不到就回到刘海屏；也可以固定成**内置刘海屏**或**主显示器**（带菜单栏的那块，不是「当前正在操作的屏幕」）。插拔显示器、改分辨率或切换排列后会自动重贴到所选屏幕顶边。

**状态栏**（默认关闭，可在通知岛的「菜单栏与位置」里打开）：图标右下角跟着状态变色（运行蓝、等待橙、结束绿、终止红），悬停提示写明当前会话，右键菜单第一行显示状态，并可直接打开「通知岛」。

## 用量

顶栏第四个 tab「用量」把三家的额度集中显示；刘海面板的胶囊里也会显示当前这一家的剩余额度（齿轮左边：环形进度 + 来源图标，鼠标停半秒弹出明细卡，点击切换来源）。

- **Codex**：读 `~/.codex/auth.json`（`CODEX_HOME` 优先）里的 OpenAI 登录信息，请求 ChatGPT 的额度接口，窗口按长度归类成「5 小时滚动 / 本周」。只读取凭据：不刷新 token、不回写文件；登录过期会提示在终端运行一次 `codex`（它会自己刷新），只配了 API Key 时会说明额度需要 ChatGPT 订阅。
- **OpenCode Go**：额度百分比与重置时间来自官方用量接口 `opencode.ai/zen/go/v1/usage`（口径与 CodexBar 一致：接口返回的 `percent` 是「已用百分比」，`rate-limited` 表示该窗口已经限额）。Key 的读取顺序是：**「用量 → OpenCode Go → API Key」里手动填写的 Key** → 环境变量 `OPENCODE_API_KEY` → `~/.local/share/opencode/auth.json` 里 opencode-go 的本机登录；手动 Key 保存前会先调一次接口验证，页面不回显已保存的 Key（只显示尾号）。接口不可用时退回本机估算：只读 `~/.local/share/opencode/opencode.db` 里 `opencode-go` 的调用费用，按 5 小时 $12 / 本周 $30 / 账单月 $60 折算（步骤级费用优先、周窗口按 UTC 周、账单月按本机最早一条记录锚定），数据库没有 `-wal/-shm` 时用 immutable 模式直读、不会在 OpenCode 目录里新建文件。两种情况下页面下方都会列出最近 30 天的每日花费与按模型汇总（来自本机数据库）。
- **Antigravity（agy）**：各模型组（Gemini、Claude / GPT）的 5 小时滚动与周配额窗口，两条通道取值——本地 Antigravity Language Server 的 `RetrieveUserQuotaSummary`（需要给它地址与 CSRF token：环境变量 `ANTIGRAVITY_LS_ADDRESS` / `ANTIGRAVITY_CSRF_TOKEN`，或 `~/.bobo/agy-auth.json` 缓存；bobo 不扫进程，没给就跳过）与 agy CLI 的 `/usage` 报告（`agy -p /usage --output-format json`，用本机登录，与 CodexBar 同一调用；没装 CLI 或没登录会给出对应提示）。两条都只读，页面下方会说明这一份数据来自哪条通道。
- 数据每分钟检查一次：走接口的来源 3 分钟读一次（手动刷新最快 60 秒一次），纯本机读数每分钟一次；读取失败（含 OpenCode Go 接口失败降级到本机估算）会按 2 / 4 / 8 / 10 分钟递增退避，成功后立刻回到正常节奏——不会每分钟白试一次打不通的接口。网络失败时保留上一次成功的数据并标出错误。停留在「用量」页面时每分钟拉取一次，也可以点右下角的悬浮「刷新额度」按钮；鼠标停到刘海胶囊的额度指示上、明细卡弹出时也会顺手触发一次（与手动刷新同样受 60 秒硬下限约束）。
- **额度重置提醒**（Codex 与 Antigravity）：额度窗口从「用过」（剩余 < 100%）回到 100% 时提醒一次——系统通知 + 提示音（`Hero`）。开关在「用量」页的「额度重置时提醒」里（默认开，保存在 `~/.bobo/usage.json` 的 `notifyReset`）；系统通知与提示音还受「通知岛」的两个开关控制。服务刚启动（没有上一次读数）、上一次不可用或这次降级到本机估算时都不比较，不会误报。
- 刘海胶囊的额度默认是**展开并排**（「通知岛 → 内容 → 额度查看方式」可切换）：折叠时只显示**默认展示的额度**（同一分栏里选，默认「自动」= 第一个可用来源；点「用量」页里的来源也能改，点圆环不会改它；鼠标停半秒看这一家的明细），面板展开时把所有可用且开启的来源并排显示出来，鼠标停在哪一枚就看哪一家（卡片里折叠胶囊那家带「当前」徽标，圆环当前画的那一档窗口标题加粗提亮），点某一枚圆环就在这一家的窗口之间循环（5 小时 / 本周 / 账单月…，比如把 OpenCode Go 切到「账单月」就画账单月的剩余），选择按来源记在本机、重开也还在；并排的数量按屏幕剩余空间自适应（不越过面板中轴线），也可以固定成最多 3 / 5 / 7 家。切回「点击切换」就是原来的一枚圆环（点它在可用来源之间循环；圆环画的是当前那家记住的那一档窗口）。每个来源在「用量」页面里都有一条启停开关，关掉的来源只在这里查看、不参与刘海胶囊的并排显示与切换。选择与启停保存在 `~/.bobo/usage.json`（权限 0600，手动填的 API Key、各来源的显示范围也放在这里）；额度查看方式与并排数量是通知岛设置，存在 `~/.bobo/opencode.json`。数据是本机估算（OpenCode Go 的降级路径）或账号返回值（Codex 与官方接口），不会写入任何远端状态。

## 设备

顶栏第五个 tab「设备」显示本机 CPU、内存与磁盘三项指标（只读、不联网、不写任何文件）；刘海面板折叠态的胶囊里、额度指示的右边也有一枚设备指示，悬停看同样的明细，点击打开窗口并切到「设备」。

- **CPU**：整机占用率按 2 秒窗口的 CPU 时间差计算（`os.cpus()` 的累计时间，与「活动监视器」同一来源）；页面还会列出 1 / 5 / 15 分钟负载均值、每个核心的占用条，以及按 CPU 占用排序的 Top 进程（见下一条）。
- **内存**：解析 `/usr/bin/vm_stat` 的页统计，**已用 = 活跃 + 联动 + 压缩占用 − 可回收**，缓存（非活跃页）单独列出，口径接近「活动监视器」（macOS 的 `os.freemem()` 只报 free 页，几乎永远是 0，不能用）；内存压力等级读内核的 `kern.memorystatus_vm_pressure_level`（正常 / 警告 / 紧张），压力警告或紧张时会抬高卡片的配色等级。
- **磁盘**：按 APFS 容器统计（`fs.statfs('/')`），容器里所有卷共享同一份可用空间，与 Finder 显示的一致。
- **进程列表**（CPU 与内存分栏各一份）：只读 `/bin/ps -Ao pid=,pcpu=,pmem=,rss=,etime=,comm=`，一次 fork 拿全部进程，按 CPU 占用或常驻内存（RSS）排序后各取前 15 条。它是**按需采样**：只在设备视图的 CPU / 内存分栏可见、且页面在前台时每 3 秒拉一次 `/api/devices/processes`，切走分栏、离开视图或切到后台立刻停；服务端结果缓存 1.5 秒，多开页面或重复请求只落一次 `ps`。进程列表不进常驻采样、也不进状态流（刘海面板用不到）。口径提醒：`ps` 的 %CPU 是进程生命周期的衰减平均值、内存列是 RSS，与「活动监视器」的瞬时值和「实际内存」接近但不完全等价。bobo 自己的进程（本机 node 服务与 `bobo.app`）固定排在表格最前（带「服务」/「应用」小标签），不参与排序与前 15 条截断。
- 服务端每 2 秒采样一次 CPU、约 6 秒一次内存、约 60 秒一次磁盘，结果挂在状态流里（刘海面板不用另外轮询）；停留在「设备」页面时每 2 秒拉一次快照，也可以点右下角的悬浮「刷新设备」按钮立刻全量采一次（`?refresh=1`，不必等磁盘那 60 秒，撞上常驻跳也不会拿回旧快照）。刘海胶囊里悬停额度 / 设备指示、明细卡弹出时也会顺手触发一次对应来源的刷新。没有可见变化时不推送：CPU 按 5% 粒度、内存与磁盘按 0.1% 粒度去重。
- **刘海胶囊上的设备指示**：外环上 260° 是磁盘占用、下 100° 是内存占用（比 2/3 / 1/3 再多一点，磁盘那条明显超过半圆）；两条进度都从左侧那端起长——**存储顺时针**往上绕过顶部，**内存逆时针**沿下弧向右（下弧顺时针会顶进存储那一段），到满时正好铺满各自那一段；左侧（约 8 点）与右侧（约 4 点）各留 14° 缺口，两段不会糊成一整圈。颜色按占用率分三档：**≥ 85% 红、≥ 75% 橙、其余是健康色**（磁盘白、内存青），中心圆点 = CPU 压力灯（绿 < 50% / 橙 < 80% / 红 ≥ 80%）。鼠标停在上面半秒弹出明细卡（CPU 占用率与负载、内存用量与压力、磁盘用量与可用空间），点击打开窗口并切到「设备」。

## macOS 应用

已安装到 `/Applications/bobo.app`。应用默认只保留屏幕顶部的刘海面板，不在菜单栏放图标；同时按窗口状态在 Dock 中动态出现：窗口打开时是普通应用，会进入 Dock 与 ⌘Tab 切换器，关闭窗口后自动从 Dock 与 ⌘Tab 中隐藏。刘海右侧有一个齿轮按钮，点它（或点刘海其它位置）打开主窗口；如果更习惯菜单栏入口，可以在「通知岛 → 菜单栏与位置」打开「显示状态栏图标」，恢复菜单栏图标与它的右键菜单。

应用使用系统 AppKit + WebKit，界面是一套深色优先的卡片式设计（深底、卡片、蓝色强调），跟随系统深/浅色（也可在「设置 → 外观」里固定）：窗口没有原生标题栏，顶栏与红黄绿灯连成一体：应用图标与应用名贴顶居中，和红黄绿灯同处一条水平线，下面一行左侧是「通知岛 / 用量 / 技能 / 智能体 / 设备 / 设置」六个常驻 tab 标签，右侧是 GitHub 入口与版本按钮——版本按钮同时是更新入口：默认显示版本号，检查中 / 下载中（带百分比）/ 已就绪会直接变成对应文案，点一下执行检查或重启安装，不需要进设置页。首次打开时自动启动内置的本地服务。打开状态栏图标后，左键点击它切换窗口显示/隐藏，右键（或 Control+左键）弹出菜单，可打开 bobo、跳到通知岛、重置刘海位置或退出；刘海面板始终可用。关闭窗口（红灯或 ⌘W）只会隐藏界面，应用继续驻留；⌘Q 或菜单里的「退出」才会结束自己启动的服务。如果服务已由终端启动，则复用并保留该服务。

应用包包含网页与服务的独立副本（`Contents/Resources/` 下的 `src/` 与 `public/`），仍使用本机 Node.js（不需要 npm / npx）。源码变更后运行 `./update.sh` 即可：它调用 `scripts/build-app.sh` 构建（版本号取自 `package.json`，写进 Info.plist），覆盖安装 `/Applications/bobo.app`，退出正在运行的旧应用后打开新版本；可传路径参数指定其他安装位置。构建先写到临时目录，失败不会破坏已安装版本。改名后首次运行时，旧安装 `/Applications/Skills Manager.app` 会被自动退出并移除，数据目录 `~/.skills-manager` 的内容会逐项迁移到 `~/.bobo`（`~/.bobo` 里已存在的文件不会被覆盖）。

**应用内更新**：安装版会在启动约 15 秒后静默检查 GitHub Release，发现新版本自动在后台下载 `bobo.app.zip`、校验 sha256 与代码签名并解压暂存到 `~/.bobo/updates/`；**顶栏右上角的版本按钮就是更新入口**——检查中 / 下载中（显示百分比）/ 已就绪都直接显示在按钮上，已就绪时点一下（确认框里有更新说明）即重启安装：应用退出，独立的重启脚本按 PID 分级退出应用（先 AppleScript、1 秒后退化为 SIGTERM / SIGKILL）、等 4318 释放后替换 `bobo.app` 并重新打开（替换失败会回滚旧包，全程写 `~/.bobo/updates/relaunch.log`）。重启后如果暂存还在，会直接回到「已就绪」状态。源码运行（不是从 `.app` 启动）不提供应用内更新，请用 `./update.sh`；版本发布见「发布」一节。

## AI 翻译与能力总结

「设置 → AI」可配置 OpenAI 兼容 API 地址（例如 `https://api.deepseek.com`）、模型和 Key 来源。接口须支持 `/chat/completions`；可使用兼容网关或本机服务。技能与智能体共用同一套能力：技能面向 SKILL.md 与子文件，智能体面向单个定义文件，分段对齐、分批翻译与缓存规则一致。

- **读取系统**：优先使用服务进程的 `OPENAI_API_KEY`，macOS 下缺失时读取 `launchctl getenv OPENAI_API_KEY`，再尝试 `~/.zshrc`；也可选择「读取 ~/.zshrc 的 OPENAI_API_KEY」直接使用文件配置。支持 `export OPENAI_API_KEY="..."`、单引号及无引号的单行字面量赋值和行尾注释，重复赋值取最后一项。不支持变量展开、命令替换、跨行或 source 引用，不执行 shell 文件。未手动保存地址、模型时，分别读取 `OPENAI_BASE_URL` 和 `OPENAI_MODEL`，默认使用 DeepSeek 地址和 `deepseek-v4-flash`。在终端通过 `npm start` 启动会继承终端的环境变量；Finder 启动的应用通常不会继承 `.zshrc`，可直接选择读取 ~/.zshrc，或使用手动配置及已有的 launchctl 环境。不会扫描其他应用的凭据文件。
- **手动配置**：Key 保存在 `~/.bobo/ai.json`，文件权限为 `0600`，属于本地明文配置；不进入技能备份。页面只接收是否配置及来源，不回显 Key。留空保持原 Key，可单独清除已保存 Key。
- **能力总结**：在正文顶部点击生成，说明技能用途、核心能力、适用场景、输入产出、示例和限制。生成时实时流式显示，可展开、收起或复制，不再弹出结果窗口。
- **翻译全文**：对当前打开的文件（SKILL.md 或任意子文件）按段落显示「原文在上、中文在下」，按钮位于顶部操作栏、紧挨「能力总结」；同一分段规则与稳定段落 ID 保证对齐。代码块只保留原文；声明块默认展开（可手动折叠，折叠状态在重新渲染时保留），字段以键值表格显示，展开后可查看字段与译文的对照。首批优先翻译 2 段，其余每批最多 6 段、最多两批并行；完成一批立即推送到正文并缓存，失败后点击「继续翻译」只请求尚未完成的段落。不同文件各自缓存，互不覆盖。

默认使用排版后的阅读视图，可切换「编辑」操作原始文件。点击能力总结时只发送当前技能**已保存的 SKILL.md**，点击翻译时发送当前打开文件的已保存内容到所配置服务；不执行文档中的指令。修改须先保存才能切换阅读或生成。

摘要和译文持久化于 `~/.bobo/ai-cache/`，刷新页面、重启应用均可复用。缓存绑定技能文件版本、目录身份、目标文件路径、模型、API 地址和提示词版本。编辑技能文件、支持文件变化、更新或删除技能时失效；即使更新后正文没变，也需要重新生成。同路径重新安装不会复用旧缓存，更新过程中迟到的 AI 响应不会恢复已失效的缓存。AI 配置变更后使用新缓存；Key 不写入缓存。

支持不超过 180 KB 的单个文件；每次模型请求最长 120 秒。DeepSeek 模型的摘要与翻译均显式发送 `thinking: {"type":"disabled"}`，关闭思考。摘要使用 SSE 接收增量，再通过本地流式响应直接推送页面；兼容服务若返回普通 JSON，也能显示结果，不额外重发请求。切换技能不会把生成结果插入其他技能，返回或刷新后可继续查看进度。全文完成后可复制译文，摘要可独立复制，均不改写原始文件。AI 输出需对照原文核实。

顶部与技能工具栏按使用频率分层：主要动作直接可见，低频与破坏性操作收进「⋯」菜单（删除类操作在菜单底部独立成行）。菜单支持点击面板以外或按 Esc 收起，按钮均带悬停提示并支持键盘焦点与减少动态效果偏好。

`npm test` 还包含隔离的模拟 AI 接口测试，覆盖系统 Key、配置持久化和权限、翻译/总结请求、鉴权/额度错误、重定向拒绝及失败恢复；正文缓存测试还覆盖持久化、逐段对齐、续译、更新/重装失效和迟到响应。测试不会使用真实 API Key 或消费模型额度。

流式回归测试覆盖首字在请求结束前到达、跨网络块的中文 UTF-8、关闭思考参数，以及双批次并发和缓存完整性。

## 发布

发布包用 **Developer ID 签名 + Apple 公证**（`Developer ID Application: Yonghao Yang (LGKLTGNTY2)`），别人下载后 Gatekeeper 直接放行；应用内更新只接受同一团队的签名。

### 本机发布（当前默认路径）

1. 更新 `package.json` 的 `version`，把变更写进 `CHANGELOG.md`（beta 轮次写成 `1.3.0-beta.1` 这种带后缀的形式，发版时保持 tag 与它一致）；
2. `npm run package`：构建 → 签名（硬化运行时 + 安全时间戳）→ 提交 Apple 公证并等待 → staple → Gatekeeper 校验 → 输出 `dist/bobo.app.zip` 与 `.sha256`；
3. 打 tag 并推送：`git tag v1.2.1 && git push origin v1.2.1`（Release 工作流没有签名 secrets 时会跳过打包、只跑测试）；
4. 创建 Release：`gh release create v1.2.1 dist/bobo.app.zip dist/bobo.app.zip.sha256 --title v1.2.1 --generate-notes`；beta 轮次同理（`v1.3.0-beta.1`），但**不要加 `--prerelease`**——应用内更新读的是 `/releases/latest`，预发布 Release 它看不到；
5. 应用内更新读取该 Release 的 `bobo.app.zip`（按语义化版本比较，beta 也会提示），用 GitHub 资产的 sha256 digest 与代码签名双重校验后再安装。

- 公证凭据：本机钥匙串里的 notarytool profile（默认 `paperrss-notary`，可用 `NOTARY_PROFILE` 覆盖），或 `NOTARY_API_KEY` / `NOTARY_API_KEY_ID` / `NOTARY_API_ISSUER_ID`（App Store Connect API Key）。
- 没有 Developer ID 证书时会退回 ad-hoc 签名：`npm run package` 默认拒绝发布（本机验证可加 `BOBO_ALLOW_ADHOC=1`），`BOBO_SKIP_NOTARY=1` 可跳过公证。
- `./update.sh`（本机安装）同样走签名构建，但不需要公证。

### GitHub Actions 自动发布（可选）

在仓库 secrets 里配置以下项后，推 `v*` tag 就会在 CI 里完成签名、公证与发布（**beta 轮次也不要加 `--prerelease`**：应用内更新读 `/releases/latest`，标成预发布的 Release 它看不到——版本号里的 `-beta.N` 后缀已经能说明这是预览版）：

| Secret | 内容 |
| --- | --- |
| `BUILD_CERTIFICATE_BASE64` | 导出的 Developer ID 证书（.p12）base64 |
| `P12_PASSWORD` | 导出 .p12 时设置的密码 |
| `KEYCHAIN_PASSWORD` | CI 临时钥匙串的任意密码 |
| `NOTARY_API_KEY_P8` | App Store Connect API Key（.p8）base64 |
| `NOTARY_API_KEY_ID` | API Key 的 Key ID |
| `NOTARY_API_ISSUER_ID` | API Key 的 Issuer ID |

导出证书：钥匙串访问 → 我的证书 → 右键 `Developer ID Application: Yonghao Yang` → 导出为 .p12（设置密码），然后 `base64 -i cert.p12 | pbcopy` 填进 secret。CI（`.github/workflows/ci.yml`）在 push / PR 时只跑 `npm test`。
